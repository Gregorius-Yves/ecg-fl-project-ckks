Panduan Konsep CKKS Homomorphic Encryption
1Apa itu Homomorphic Encryption?
Teknik kriptografi yang memungkinkan komputasi langsung pada data terenkripsi tanpa harus mendekripsi terlebih dahulu. Hasil komputasi, setelah didekripsi, identik dengan hasil komputasi pada data asli.
💡 Analogi: Anda bisa menjumlahkan isi dua brankas terkunci tanpa membukanya — hasilnya tetap benar saat brankas dibuka.
2Apa itu Skema CKKS?
CKKS (Cheon-Kim-Kim-Song) adalah skema HE yang dirancang khusus untuk bilangan desimal (floating-point). Cocok untuk bobot model AI yang berupa vektor angka desimal. Menggunakan Ring-LWE dan polynomial encoding dengan keamanan 128-bit pasca-kuantum.
🔬 Parameter: FL-D1-N16384 → LogN=14, 8.192 slot per ciphertext, depth 1 (server-weighted multiplication + summation).
3Mengapa HE untuk Federated Learning?
FL standar mengirim bobot model plaintext ke server — server bisa membaca update tiap klien. Dengan CKKS, klien mengenkripsi bobot sebelum dikirim. Server mengagregasi ciphertext secara homomorfik dan hanya mendekripsi hasil agregat. Bobot individu klien tidak pernah terlihat oleh server.
🛡️ Perlindungan: Server hanya melihat data terenkripsi acak — zero knowledge terhadap update individual.
4Pipeline CKKS di Sistem Ini
1. Klien melatih model lokal → 2. Bobot di-flatten menjadi vektor float64 → 3. Vektor dipecah menjadi 33 chunk (8.192 slot) → 4. Tiap chunk dienkripsi via Go sidecar (Lattigo v6) → 5. Ciphertext dikirim via Flower gRPC → 6. Server: Mul(ct, weight) + Add homomorfik → 7. Decrypt agregat → model global baru.
⚡ Overhead: ~160ms encrypt, ~70ms aggregate, ~23ms decrypt per ronde — presisi ~28 bit (MAE < 5×10⁻⁸).
